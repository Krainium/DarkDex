# darkdex v2

someone who was using a packed streaming app (call it `com.example.player`) came to
me because darkdex could not get the real code out of it. the app shipped one of
the strong ijiami 4th gen builds, and on those the dump came back empty or full of
garbage. v1 already cracked most packers by running the app under redroid and
reading its memory from the host, so this was a good push to go back and rebuild
the parts that fell over on the hard builds. that rebuild is v2.

## what v1 could not beat

v1 took one snapshot of the process memory and carved the dex out of it. two
tricks in the strong ijiami builds walk right past a single snapshot.

first, header wiping. the packer hands a real, valid dex to the runtime, lets it
map and load, then zeroes or fakes the header back in memory. a snapshot taken
after that finds nothing usable. v1 had a fallback for a wiped header: it anchors
on the map_list, the one section the runtime has to keep intact to run the code,
and rebuilds the header from that. but a packer can chew up the map_list too.

second, lazy release. the code comes out one class at a time, right before it
runs. a single snapshot only holds whatever has already executed. everything the
user has not reached yet is still sealed.

both of these beat one photo. so v2 stops taking a photo and starts watching.

## the fix: watch the runtime open the dex

the runtime has to be handed a real, valid dex to run it. so there is always a
moment, inside the function that opens a dex out of a memory buffer, where the
fully decrypted dex sits in plain view before the packer wipes anything. v2 sits
on that moment. it puts kernel probes (bpftrace uprobes) on the runtime from the
host, so the app never sees them, same as reading process memory but live instead of a one time grab.

the three probes it uses on android 11:

| probe | what it hands you |
|---|---|
| `art::DexFileLoader::OpenCommon` | `arg0` is the buffer, `arg1` is the size, for every dex the runtime opens from memory, decrypted and valid, caught before any wipe |
| `art::CompactDexFile::CompactDexFile` | the same but for CompactDex (`cdex001`) |
| `art::ClassLinker::DefineClass` | the class name (`x2`) as each class is defined, so you also get a live list of every class and you catch the lazy released ones as they load |

because the probes live in the kernel, the packer's anti debug never notices, and
because they fire on every event, they keep firing through the respawns ijiami
does under its anti tamper. `darkdex_grab` reads the events, pulls each dex out of
`/proc/<pid>/mem` at the buffer address while it is still good, drops duplicates by
content, and keeps only the target by checking each pid's cmdline.

on the app that started all this, the tracer pulled the main app dex at roughly
9,600 classes, larger and cleaner than the best snapshot (around 7,400), and
baksmali disassembled the whole thing into real app source
(`com/example/player/ui/HomeActivity` and friends) plus the packer's own classes
(`com/ijiami/...`).

## when the header and the map_list are both gone: artwalk

if a packer wipes the header and the map_list, carve and recover are both blind.
but the runtime still knows the truth. every loaded dex has a live `DexFile` object
on the heap whose fields hold the real start address and size, and those do not
depend on the bytes on disk at all. `darkdex_artwalk` walks the heap for those
objects (the vtable points into the runtime libraries, the start points at a real
page, the size is sane) and dumps each dex by the bounds the object records. this
works even when the header is total garbage, and it needs no version specific
offsets. on the same target it pulled 28 dex straight from live objects.

## CompactDex that would not decompile

v1 only stamped the standard magic on a CompactDex and left the compact code items
in place, so the output would not open in any decompiler. v2 does the real work.
it walks every method, reads the compact code item (the two 16 bit header words
that pack registers, ins, outs, tries and the instruction count, with the big
values sitting in a small back read preheader), rebuilds a standard code item,
rewrites each method's offset, and repoints the class data. debug offsets are set
to zero, so you lose local variable names but the code opens fine.

## validate, dedup, rank

the tracer, carve, recover and artwalk all overlap. `dexval.py` parses each dump
against the dex format, throws out the invalid and the duplicate ones by content
hash, ranks the app dex above the framework dex (it rewards class names that are not android or java framework packages), copies the winners into `best/`, and if baksmali is on the path it smoke tests that the top dex actually disassembles.

## where this sits in the research

the move from a snapshot to watching the runtime live, and doing that watching from the kernel so the app cannot see it, is the direction the recent work has
landed on.

* BPFDex (IEEE TIFS, 2025, Li et al.) does robust unpacking through the android Kernel and eBPF, so the collector sits below anything the app can hook. v2's
  tracer is the same idea done with bpftrace on the runtime's dex open path.
* FART and DexHunter drive or watch class loading so the lazy released code gets materialised. v2's DefineClass probe gets that coverage as the app runs, with no in process agent for the packer to spot.
* PackerGrind and AppSpear push adaptive, many pass dumping, which is why v2 runs several collectors and reconciles them in dexval.
* Happer (IEEE S&P, 2021, Zhang et al.) does hardware assisted unpacking, same goal of watching from a layer the packer cannot reach, heavier machinery than uprobes.
* "To Unpack or Not to Unpack" (2025, Asghari and Zhao) measures how common these commercial packers are and ships Purifire, an eBPF tool that bypasses the anti analysis at runtime instead of unpacking, the same out of sandbox line v2 takes.

* To Unpack or Not to Unpack (Purifire): https://arxiv.org/abs/2509.16340

## running it

```
# one shot: trace, snapshot, convert, validate, winners land in dumps/<pkg>/best/
./host/darkdex.sh com.example.player --baksmali
./host/darkdex.sh app.apk                  # installs it first, then unpacks
./host/darkdex.sh com.example.player --no-trace  # snapshot only
```
